# Acceptance matrix: Zlatura (from Comp Loader 3.3.0)

Baseline: `main` at the merge of pull request #3 (content identical to commit
`8ddc4e9`), version 3.3.0, audited 2026-10-10. This file tracks every feature
in the Zlatura development brief. It supersedes `docs/ACCEPTANCE.md` (the 3.2.0
matrix), which stays as the detailed record of how 3.2.0 was tested.

## Status vocabulary (brief, Part 23)

| Status | Meaning |
|---|---|
| Implemented and verified | Built, tested at the level stated, evidence named |
| Implemented, not fully tested | Built; test gaps listed |
| Tested with synthetic fixtures only | No real-world document or service validation |
| Tested with live services | Real provider calls verified; date and method recorded |
| Blocked | Missing credentials, infrastructure or access (stated) |
| Partially implemented | What exists and what is missing |
| Not implemented | Not started |

"Synthetic fixtures" means the invented OMs, CoStar reports, rent rolls and
workbooks generated by `tests/e2e/make_pdfs.py`, `make_tpl.py`, `make_model.py`
and `tests/fixtures.js`. No real brokerage file has been used. No test has run in
Safari, Firefox or Microsoft Excel; workbooks are recalculated in LibreOffice.

Evidence names: unit tests are `tests/*.test.js` (133 pass); browser flows are
`tests/e2e/*.mjs` run by `tests/e2e/run.sh` (20 flows plus LibreOffice
recalculation of 9 exported workbooks; all pass on the baseline).
